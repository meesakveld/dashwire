## Overview

`@dashwire/server` is the self-hosted runtime for Dashwire. It combines the project API, Socket.IO namespaces, SQLite persistence, database migrations, and the bundled dashboard application.

Connected projects use the `/sdk` realtime namespace. Dashboard clients use `/dashboard` to subscribe to projects, receive state and log updates, and send capability commands or actions.

## Installation

```bash
npm install @dashwire/server
```

```bash
pnpm add @dashwire/server
```

The package includes the compiled server and the bundled dashboard assets. For most deployments, run it as the application server for a Dashwire instance.

## Usage

Build the package from a checkout of the Dashwire repository:

```bash
pnpm --filter @dashwire/server build
pnpm --filter @dashwire/server start
```

The server listens on port `4000` by default and exposes a health endpoint:

```bash
curl http://localhost:4000/health
```

Expected response:

```json
{ "ok": true }
```

For local package development:

```bash
pnpm --filter @dashwire/server dev
```

## Configuration

The server reads deployment values from environment variables. The starter project generated by Dashwire provides a baseline `.env` file and Docker Compose configuration.

Common deployment values include:

| Variable | Purpose |
| --- | --- |
| `PORT` | HTTP and dashboard listening port; defaults to `4000` |
| `DASHWIRE_DB_PATH` | SQLite database location used by the deployment |
| `JWT_SECRET` | Secret used for authentication tokens |

Use environment-specific secrets in production and keep them out of version control.

## Runtime Responsibilities

- Serves the bundled dashboard and HTTP API
- Registers connected projects and tracks online status
- Persists capability state and logs in SQLite
- Relays capability commands and actions over Socket.IO
- Runs Drizzle database migrations during startup
- Provides project and dashboard realtime namespaces
